How to read the data

Sources, reporting units, and measures of asylum processing pressure.

Sources and scope

The chapter uses the repository’s saved UNHCR application and decision CSVs for 2000–2025. Application, decision-outcome, processing-ratio, and reporting-coverage charts are calculated from those pinned CSV snapshots. The observed pending-stock chart is generated from a separately saved UNHCR worldwide annual population-API response.

Persons, cases, and events

Application and decision series combine original P (persons) and C (cases) values without conversion or a case-size multiplier. They represent mixed-unit reported activity, not unique people or harmonised case counts. Reporting-unit mixes can differ between flows, countries, and years, affecting ratios and comparisons. The source notebook retains its original persons-only worldwide charts; the website now uses a combined-unit presentation calculated from the same pinned inputs.

Application events are not a count of unique individuals across the study period. The source distinguishes new applications, repeats, appeals, and other types. Missing type codes are retained as Other / unspecified.

The pending-stock series is a separate population measure. It is not restricted to precisely the same country-year reports as the flow charts.

Decision shares and recognition rates

Let R be recognised refugee-status decisions, C complementary-protection decisions, J rejections, and A administrative closures.

Measure Numerator Denominator
Recognised share of all decisions, used in the chart R All recorded decisions, including A
Refugee recognition rate among substantive decisions R R + C + J
Total protection rate among substantive decisions R + C R + C + J

The chart uses annual decision counts. It does not follow an application cohort. Composition can change with the mix of reporting countries, applicants, and procedures.

Definitions follow the UNHCR asylum statistics explainer. Administrative closures are not necessarily substantive refusals.

Reporting coverage

The coverage chart counts distinct receiving-country ISO codes with at least one persons- or case-reported row in each file and year. It counts presence, not completeness. It does not verify that every reporter submitted all procedures or a complete annual return.

Codes are not necessarily a fixed set over time. Records can describe historical or special entities; the chart therefore uses “receiving-country codes.”

Checks used in the analysis

  • Validate reporting units and check for negative volumes.
  • Preserve raw totals through grouping.
  • Retain rows with unspecified application type.
  • Aggregate application types before joining to avoid duplicated decisions.
  • Retain decision-only rows through an outer join.
  • Check that both totals are independently conserved.
  • Refuse preparation when code or input snapshots differ from the verified execution.

Reproduce the sample

Run these commands from the python-charts repository:

python scripts/prepare_quarto_preview.py
python scripts/style_publication_charts.py
quarto preview quarto-preview

Preparation reads the executed notebook and local CSVs, checks their identities, preserves the pending-stock image, and generates the combined-unit flow, outcome, processing-ratio, and coverage figures and supporting text. It does not download fresh data or rerun the notebook.

For a new analytical edition, first refresh and verify the notebook using its execution script. Review changes in coverage and source revisions before refreshing this publication.

Limitations and reuse

This is descriptive analysis without causal inference or uncertainty estimates. Missing reports, procedural differences, revisions, and changes in reporting units affect interpretation. Missing or zero pending-stock totals are treated as unavailable for the notebook plot; that plotting choice does not establish the meaning of every source zero.

Consult UNHCR’s methodology and dataset terms before reusing figures. Cite the original sources alongside this independent analysis.

Explorer updates

The country explorer uses separate dated snapshots refreshed from UNHCR weekly and on publication updates. The narrative chapter above stays pinned to its verified notebook edition. Each refresh requests years from 2000 through the previous calendar year, validates grouping keys, counts, and units, and checks that aggregation preserves totals. A coverage loss greater than 20% against the committed baseline stops publication for review.

The two datasets are aggregated independently by receiving country, year, and unit, then combined with an outer join. Missing observations remain unavailable. Percentages appear only where all four outcomes reconcile to a positive total. No smoothing or case-to-person conversion is applied in the explorer.

Download time records retrieval, not the source release date. A latest available year may be incomplete. UNHCR links retrieve current country data, which can differ from the stored snapshot. The chart CSV and source ZIP identify the displayed data.

Processing output relative to applications

Decisions per 100 applications = 100 x recorded decisions / reported applications in the same year. The numerator includes administrative closures. Values below 100 indicate lower recorded output than inflow; these differences do not by themselves establish backlog changes. Ratios do not measure resource-adjusted staff productivity, quality, or waiting times. No ratio is calculated with a zero or unavailable application denominator.

Display rounding

Percentages are displayed as whole numbers, with one decimal for values below 10%. Non-zero shares below 0.1% are shown as <0.1%. Rounded percentages may not add to 100%. Headline totals in millions use one decimal; exact counts remain whole numbers. CSV downloads retain their original precision.

Annual decision-outcome pies

The front-page yearly pies include only positive decision records with all four outcomes present and summing exactly to their recorded decision total. Each card shows the included count and its share of all reported decisions for that year. This avoids silently normalising inconsistent outcome totals into a full circle. The headline totals retain all reported records. The annual pie CSV includes both denominators and unrounded shares.
